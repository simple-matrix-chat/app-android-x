# Moment iOS screen map for Android parity

This document maps the current `app-cut-ios` main branch screens to Android areas in this repository.
Use it as the working backlog for bringing Android visuals and screen behavior closer to Moment iOS.

Scope rules:
- Calls stay in scope and must remain visible/supported on Android.
- Labs exists in upstream/iOS code, but is not exposed in the Moment Android settings navigation.
- Prefer Moment-specific iOS screens over generic Element X screens when both exist.
- Keep Android changes screen-by-screen, with screenshots before each PR.
- Keep the main Android emulator as a long-lived logged-in runtime: do not use `-wipe-data`, `pm clear`, uninstall, or other destructive app-data commands unless explicitly approved. Install updates over the existing app with `adb install -r -d` so authentication state is preserved.
- If the emulator unexpectedly shows PIN/login, stop and diagnose the existing app state instead of resetting the emulator or app data. The visible logged-in emulator is the canonical QA runtime.
- Current QA protocol supersedes older progress-log entries below. Any historical mentions of uninstalling, clearing data, or wiping the emulator are archival notes only and must not be repeated without explicit approval.
- Current canonical Android QA runtime is `emulator-5554` / `com.moment.app.debug`; verify `firstInstallTime=2026-06-28 21:31:06` before and after installs that touch logged-in runtime QA.

Status legend:
- `todo`: not checked against Android yet.
- `partial`: Android has an equivalent but visual/behavior parity is incomplete.
- `ok`: checked and close enough.
- `skip`: intentionally not copied.

## Recommended execution loop

For each screen group:
1. Open the iOS screen in simulator and capture a local reference screenshot.
2. Open the Android equivalent on the visible Android emulator and capture a local comparison screenshot.
3. Record visible differences in this file or a short PR note.
4. Patch the smallest Android module that owns the surface.
5. Run focused `ktlintCheck`, `compileDebugKotlin`, and relevant unit tests for touched modules.
6. Install `:app:installFdroidDebug` or the built APK over the existing app (`adb install -r -d`), preserving emulator/app data, then re-check the screen in emulator.
7. Treat `uiautomator dump` and source inspection as supporting evidence only; visual parity requires screenshot comparison.
8. Before any runtime-changing command, verify it preserves app data. Do not use uninstall, `pm clear`, `-wipe-data`, or fresh AVD flows unless the user explicitly approves that exact reset.
9. Only then move the screen status forward.
